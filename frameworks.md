# Сравнение LLM-фреймворков для автоматизации бизнеса

Сравнение трёх фреймворков, наиболее подходящих под задачи автоматизации бизнес-процессов на Python: **LangChain**, **LlamaIndex**, **Haystack**.

---

## 1. LangChain

**Назначение.** Универсальный «швейцарский нож» для сборки LLM-приложений: чейнинг (последовательные цепочки вызовов LLM и инструментов), агенты, интеграции со сторонними сервисами.

**Ключевые особенности:**
- Самая большая экосистема интеграций: OpenAI/Anthropic/локальные модели, векторные БД (Chroma, Pinecone, Qdrant, pgvector), CRM, почта, таблицы и т.д.
- LangChain Agents + LangGraph — построение агентов с инструментами, памятью и циклами (state machine).
- LangSmith — трассировка, отладка и мониторинг пайплайнов.
- Огромное сообщество, много готовых примеров и туториалов.

**Сильные стороны:** гибкость, скорость прототипирования, огромное число интеграций, активная разработка.

**Слабые стороны:** высокая абстракция скрывает детали («магия»), API часто меняется между версиями, для простых задач избыточен.

**Стек:** Python (основной), есть порт на JS/TS.

---

## 2. LlamaIndex

**Назначение.** Фреймворк, заточенный вокруг данных: подключение ваших документов, индексация и поиск по ним (RAG — Retrieval-Augmented Generation).

**Ключевые особенности:**
- Богатый набор коннекторов к источникам данных (LlamaHub): PDF, Notion, Google Drive, Confluence, SQL, сайты.
- Готовые индексы: векторный, древовидный, графовый, сводный (summary) — выбор под тип задачи.
- «Из коробки» решает сложные RAG-задачи: reranking, chunking, query routing, multi-document QA.
- LlamaParse — качественный парсинг сложных PDF (таблицы, макеты).

**Сильные стороны:** лучший в классе для поиска по документам; меньше кода для RAG, чем в LangChain; хорошая документация.

**Слабые стороны:** в роли «общего» фреймворка уже, чем LangChain — агенты и интеграции слабее; сложные многошаговые пайплайны требуют костылей.

**Стек:** Python (основной), есть TS-порт.

---

## 3. Haystack

**Назначение.** Продакшн-ориентированный фреймворк (от deepset) для построения поисковых и вопросно-ответных систем: RAG, семантический поиск, классификация.

**Ключевые особенности:**
- Декларативные пайплайны: компоненты (retriever, generator, ranker, converter) соединяются в DAG в YAML или коде.
- Сильная поддержка гибридного поиска: BM25 + векторы + reranking.
- Компонентная архитектура — легко тестировать, заменять и масштабировать части пайплайна.
- Ориентация на enterprise: оценка качества (evaluation), версионирование, стабильность API.

**Сильные стороны:** надёжность в проде, прозрачность пайплайнов, гибридный поиск, стабильность API.

**Слабые стороны:** меньше готовых «коробочных» сценариев, порог входа чуть выше, сообщество меньше, чем у LangChain.

**Стек:** Python.

---

## Где пригодится в автоматизации бизнеса

### RAG по внутренним документам компании
- **LlamaIndex** — основной выбор. Быстро подключить базы знаний: регламенты, договоры, база знаний поддержки, HR-документы. Встроенный chunking, индексация и query routing закрывают 90% задачи с минимумом кода.
- **Haystack** — когда нужен промышленный поиск: гибридный BM25+векторы по тысячам документов, строгий контроль качества ответов.
- **LangChain** — если RAG — лишь один из шагов в более крупном процессе (например, «найти ответ в документах → отправить письмо клиенту»).

### Агенты для рутинных процессов
- **LangChain (LangGraph)** — основной выбор. Многошаговые агенты с инструментами: обработка входящих писем и заявок, автогенерация отчётов, классификация обращений и маршрутизация, работа с CRM/календарём/таблицами.
- **LlamaIndex** — агентные сценарии, где в центре — данные компании (агент-ассистент по базе знаний).
- **Haystack** — только простые линейные пайплайны; для сложных агентов не предназначен.

### Поисковые пайплайны
- **Haystack** — основной выбор: внутренний корпоративный поиск, FAQ-боты, поиск по тикетам поддержки. Декларативные пайплайны легко поддерживать и масштабировать.
- **LlamaIndex** — быстрый MVP поиска по документам, сложные вопросы по нескольким источникам.
- **LangChain** — если поиск — часть автоматизированного процесса с внешними действиями (уведомления, запись в БД).

| Критерий | LangChain | LlamaIndex | Haystack |
|---|---|---|---|
| Основная сила | Универсальность, агенты | RAG и работа с данными | Продакшн-поиск, пайплайны |
| Автоматизация бизнес-процессов | ★★★ | ★★ | ★★ |

| Поисковые системы | ★★ | ★★ | ★★★ |
| Интеграции | ★★★ | ★★ | ★ |
| Порог входа | Средний | Низкий | Средний/высокий |

**Рекомендация:** начинать с **LlamaIndex** для задач «вопрос-ответ по документам» и с **LangChain/LangGraph** для агентных сценариев автоматизации; **Haystack** подключать, когда поисковые пайплайны пойдут в продакшн и потребуются гибридный поиск и строгий контроль качества.

---

## Почему Semantic Kernel не вошёл в основной список

**Semantic Kernel** (Microsoft) — зрелый фреймворк с сильной интеграцией в экосистему Microsoft (Azure OpenAI, Microsoft 365, Copilot, плагины .NET). Однако:

- Основная экосистема и сильнейшая поддержка — **C#/.NET**; Python-версия заметно отстаёт по функциям и сообществу.
- Подходит в первую очередь компаниям, уже живущим в стеке Microsoft (Azure, M365).
- По гибкости агентов и RAG на Python проигрывает LangChain и LlamaIndex.

Если проекты строились бы на .NET или вокруг Azure/M365 — Semantic Kernel был бы разумным выбором. Для Python-стека автоматизации бизнеса три фреймворка выше покрывают задачи лучше.
